Get started

Install, open a solution, add a package.

NuGet LL lives in the activity bar. There is nothing to sign in to: it reads the projects in your workspace and talks to the feeds you already use.

Install the extension

From the Marketplace, or straight from your terminal.

$ code --install-extension piyushdoorwar.getll

Open a .NET workspace

Open a folder with .sln, .csproj, .fsproj or .vbproj files and select the NuGet LL icon. Projects, packages, shared props files and feeds are detected automatically.

Browse, pick projects, install

Open the dashboard, search nuget.org or your own feed, choose a version and the projects that need it, and press Install. Updates and vulnerability checks are one click away.

Requires the .NET SDK

NuGet LL drives the dotnet CLI, so the SDK needs to be on your PATH. SDK 7.0.200 or newer is recommended for the JSON reports.

Other editors

NuGet LL runs anywhere VS Code extensions do, including Cursor and Windsurf. Install it from your editor's extension view.

Features

Every dependency, in one dashboard.

The NuGet workflow you know from Visual Studio, built for VS Code and every project in the workspace.

Workspace scanner

Finds solutions, project files, Directory.Packages.props, NuGet.Config and packages.config across every workspace folder.

Browse and search

Search nuget.org or your configured feed, with prerelease and exact-id filters and a dotnet package search fallback.

Install across projects

Pick a version and the projects that need it, then install, update or remove in one step, with a confirmation before multi-project changes.

Updates with context

Outdated packages are split into patch, minor and major, so you can take the safe bumps in a batch and review the rest.

Vulnerable and deprecated

Run the SDK's vulnerability and deprecation checks, see severity per project, open the advisory and copy a report.

Central Package Management

Projects governed by Directory.Packages.props are edited the right way, and shared props files are only touched after you confirm.

Package sources

List, add, remove, enable and disable feeds through dotnet nuget, and jump to the NuGet.Config that defines each one.

Restore anywhere

Restore the workspace, a solution or a single project, with progress in the panel and the full output in the log.

Sidebar at a glance

The activity bar view counts projects, packages, outdated and vulnerable dependencies, and opens the right dashboard tab in one click.

Library Lens

Know what you're adding before you add it.

Select any search result or installed package and the details sit right beside the list, including which of your projects already depend on it.

  • Every published version, with downloads, license, authors and tags.
  • Dependencies grouped by target framework.
  • Deprecation and vulnerability notes, with links to the advisory.
  • The projects in your workspace that already use the package, and at which version.

Privacy first

Your workspace stays on your machine.

NuGet LL has no backend. It reads your project files locally and only talks to the NuGet feeds you configure.

No extension server

Search and metadata requests go straight from VS Code to nuget.org or your own feed. Nothing passes through a NuGet LL service.

Your local .NET CLI

Installs, updates, restores and health checks run through dotnet on your machine, spawned with argument arrays, never a shell.

Credentials stay put

NuGet LL never stores feed passwords. Tokens and URL-embedded credentials are masked in the log and the UI.

You approve shared edits

Edits stay inside your workspace, and shared files such as Directory.Packages.props change only after you confirm.
